## 📝 Documentation Rules

### ⚠️ CRITICAL: Markdown File Placement
**ALWAYS create new .md files in the `docs/` folder unless explicitly asked to put them elsewhere.**

- ✅ DO: Create new .md files in `/docs/` by default
- ❌ DON'T: Create .md files in the root directory
- 📋 Exception: Only if user specifically asks for a different location

### 🔗 Update HTML Index
**When creating ANY new .md file in docs/, ALWAYS add it to `docs/index.html`**

Add a new doc-card with:
- Sequential number
- Descriptive title
- Creation context/date
- Appropriate badges (type, level, status)
- Clear summary of purpose
- Link to the file

### 🚫 Avoid Redundancy
**STOP making redundant .md files after every edit**

- ❌ DON'T: Create summary files after completing work
- ❌ DON'T: Create "what we did" files repeatedly
- ❌ DON'T: Make meta-documentation about documentation
- ✅ DO: Only create new docs when adding substantial new information
- ✅ DO: Update existing docs instead of creating new ones

### When to Create New Documentation

**Create new .md file when:**
- Adding a major new feature/system
- Starting a new development phase
- User explicitly requests documentation
- Creating genuinely different content (e.g., API reference, tutorial, etc.)

**Update existing .md file when:**
- Improving existing documentation
- Fixing errors or clarifications
- Adding details to existing topics
- Small changes or additions

## ⚡ Quick Checklist

Before creating a new .md file, ask:
- [ ] Does this info belong in an existing doc?
- [ ] Is this genuinely new content?
- [ ] Did the user ask for this?
- [ ] Will I put it in docs/?
- [ ] Will I update index.html?

If any answer is NO, reconsider creating the file.

## 🗂️ Code Organization Rules

### File Management Best Practices

**When Creating Improved Versions:**

**Option 1: Update in Place** (Preferred for incremental changes)
- Edit the existing file directly
- Git tracks changes automatically
- Cleaner, single source of truth
- Use for: Bug fixes, feature additions, refactoring

**Option 2: New File + Move Old to Backup** (For major rewrites)
- Create new file with improved implementation
- Move old file to `backup_files/` folder
- Update all imports and references
- Document in backup_files/README.md
- Use for: Complete architectural changes, different approaches

**❌ NEVER:**
- Have multiple "current" versions in main directory (e.g., server.py AND temporal_server.py)
- Create parallel implementations without moving old ones
- Leave redundant files cluttering main directory

### Directory Structure

```
Main directory: Only CURRENT, ACTIVE files
test_files/: All test scripts
backup_files/: Legacy/superseded code
docs/: All documentation
templates/: Current web interfaces
```

### When Files Become Redundant

1. **Identify** - File has been superseded by new implementation
2. **Move** - `mv old_file.py backup_files/`
3. **Document** - Update backup_files/README.md
4. **Update refs** - Fix any imports/docs pointing to old file
5. **Test** - Verify system still works
